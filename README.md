# vitap-hostel-mess-data

Published mess menu data for the **VITAP HOSTEL MESS** Android app. This repository contains
**only** the public menu data the app fetches at runtime — no application source code, no
signing keys, no credentials, and no original source workbooks.

## Structure

```
menus/
  manifest.json                        version info for every published file below
  mens_vegAndNonVeg_<YYYY-MM>.json     Men's Hostel, Veg & Non-Veg combined menu
  mens_special_<YYYY-MM>.json          Men's Hostel, Special menu
  ladies_vegAndNonVeg_<YYYY-MM>.json   Women's Hostel, Veg & Non-Veg combined menu
  ladies_special_<YYYY-MM>.json        Women's Hostel, Special menu
```

### `manifest.json`

```json
{
  "schemaVersion": 1,
  "version": "<ISO-8601 UTC timestamp of this publish>",
  "generatedAt": "<ISO-8601 UTC timestamp of this publish>",
  "files": {
    "<file base name, e.g. mens_vegAndNonVeg_2026-10>": {
      "version": "<ISO-8601 UTC timestamp this specific file was last published>",
      "url": "<file name, relative to this manifest>",
      "sha256": "<hex SHA-256 of the published file's exact bytes>"
    }
  }
}
```

The app fetches this manifest on every launch. If a file's `version` hasn't changed since the
app's local cache of it, the app uses the cache and doesn't download the file again. When it has
changed, the app downloads that file, verifies its `sha256` and that its content is well-formed
and matches the expected month, and only then replaces its cache — a corrupted or invalid publish
never overwrites a working one on-device.

### A menu file

```json
{
  "year": 2026,
  "month": 10,
  "generatedAt": "<ISO-8601 UTC timestamp>",
  "days": [
    {
      "date": "2026-10-01",
      "hostel": "mens" | "ladies",
      "menuType": "vegAndNonVeg" | "special",
      "sourceDateLabel": "<the workbook's original header text this day was parsed from>",
      "items": {
        "breakfast": [ { "text": "...", "dietTag": "veg" | "nonVeg" | "unspecified", "styleTag": "...", "isAmbiguous": false } ],
        "lunch":     [ ... ],
        "snacks":    [ ... ],
        "dinner":    [ ... ]
      }
    }
  ]
}
```

`isAmbiguous: true` marks an item whose text references a specific week of the month (e.g. "2nd
week") inside a date range that covers more than one occurrence of that weekday — the importer
never guesses how to split it, so the same text is kept verbatim for every date in that range and
flagged here for a human to review.

## Where this comes from

Generated by the main application repository's importer from the hostel's Excel menu workbooks.
See that repo (private) for the importer source and the exact publishing procedure.
